## Python SDK

### v0.6.0 — Latest

- 🌐 **`durable_tools` works with any agent framework** — verified on LangGraph, LlamaIndex, the OpenAI Agents SDK, CrewAI and AutoGen. Where a framework dispatches a tool onto a worker that does not carry the caller's context, the session is recovered automatically; with several sessions open, `session.bind()` says which one you mean
- 📦 **Importing `cellaflow` no longer pulls in LangGraph** — `CellaflowSaver` loads on first use, so a process using another framework, or none, does not pay for it
- 🔑 **`durable_tools` moved to `cellaflow.durable`** — it never needed LangGraph, and living in that module hid it. `from cellaflow.langgraph import durable_tools` still works
- 🔧 **Fixed: `pip install cellaflow` alongside CrewAI or AutoGen** — the declared protobuf floor did not match what the generated stubs require at import, so a resolvable install could fail to import. The floor is now `protobuf>=5.29.0` and matches the package

### v0.5.0

<Warning>
**Breaking.** `SCOPE_SHARED` now requires `shared_on` (or an explicit `idempotency_key`)
and raises at import without one.
</Warning>

- ⚠️ **`shared_on` is required for `SCOPE_SHARED`** — names the arguments that identify the shared work, so agents may disagree about everything else and still converge on one execution
- ✅ **Fixes a silent duplicate-execution defect** — the derived key previously hashed *every* argument, so heterogeneous agents that reasoned their way to different values each derived their own key and each performed the side effect. Measured at five agents proposing five refund amounts: five charges where one was correct
- ✅ **Argument names validated at decoration time** — a typo in `shared_on` fails at import with the real parameter list, rather than silently hashing nothing and converging everything

**Migrating from v0.4.0** — name what identifies the work:

```python
# before
@tool(tool_name="issue_refund", scope=IdempotencyScope.SCOPE_SHARED)
def issue_refund(ticket_id: str, amount_cents: int) -> dict: ...

# after
@tool(tool_name="issue_refund", scope=IdempotencyScope.SCOPE_SHARED,
      shared_on=["ticket_id"])
def issue_refund(ticket_id: str, amount_cents: int) -> dict: ...
```

`SCOPE_SESSION_WIDE`, `SCOPE_AGENT_PRIVATE` and `SCOPE_STEP_LOCAL` are unchanged and keep
hashing every argument — replicas of one agent calling with different arguments genuinely
*are* different operations there, and graph-position arbitration catches the divergence
before either executes.

### v0.4.0

- ✅ **Leased tool calls inside LangGraph nodes (`durable_tools`)** — wrap LangGraph invocations to lease `@tool` calls inside node bodies, guaranteeing irreversible side effects execute at most once across node failures, container crashes, and resumed runs
- ✅ **Compatible with any checkpointer** — `durable_tools` works alongside `CellaflowSaver`, `PostgresSaver`, `MemorySaver`, or any other `BaseCheckpointSaver` without migrating checkpoint storage
- ✅ **Multi-node graph execution** — dropped positional replay in `durable_tools` so complex graphs with multiple tool-bearing nodes resume correctly without sequence mismatches
- ✅ **Robust config validation** — accepts bare string thread IDs or standard LangGraph config dictionaries, automatically hashes thread IDs containing colons to generate valid gRPC session IDs, and explicitly rejects empty thread IDs
- ✅ **Thread history pagination & error handling** — follows engine page cursors when querying thread history, and clearly distinguishes empty threads from engine read failures
- ✅ **Top-level package exports** — `durable_tools` and `tool_session_id` exported directly from `cellaflow`

### v0.3.0

- ✅ `IdempotencyScope.SCOPE_SHARED` — agents in **different sessions**, on different workflows and
  versions, converge on one execution within a named coordination domain
- ✅ **Replay verification** — a resumed run that diverges from its recorded history raises
  `NondeterministicWorkflowError` rather than returning the result recorded at that position
- ✅ **Graph-position arbitration** — replicas that disagree about a step's arguments raise
  `DivergentStepError` *before* the side effect runs
- ✅ Callers adopt the engine's reported sequence after a cache hit
- ✅ Concurrent `CellaflowSaver` instances on one `thread_id` commit against a refreshed sequence
- ✅ Lease renewal failures explain what happened and what to do about it

Requires no engine upgrade — the new request fields are optional and an older engine ignores
them.

### v0.2.0

- ✅ `@workflow`, `@step`, `@tool` decorators with full `async def` support
- ✅ `CellaflowSaver` — drop-in LangGraph checkpointer with time-travel and crash recovery
- ✅ RFC 8785 Canonical JSON + SHA-256 idempotency key derivation
- ✅ Agent-scoped idempotency (`SCOPE_SESSION_WIDE`, `SCOPE_AGENT_PRIVATE`, `SCOPE_STEP_LOCAL`)
- ✅ Background lease heartbeat management with fencing token validation
- ✅ MessagePack serialization for all state payloads (no pickle, no RCE vectors)
- ✅ `contextvars` isolation — safe for concurrent async workflows in the same process
- ✅ Low-level `CellaflowClient` for manual session management

Install: [`pip install cellaflow`](https://pypi.org/project/cellaflow/)

## CellaFlow Engine

### Latest

- ✅ **Per-commit fsync durability (`CELLAFLOW_SYNC_WRITES`)** — synchronously flushes durable writes to RocksDB WAL before acknowledging them (default `true`), ensuring committed step outputs and timer events survive host power loss
- ✅ **Hardened durable write safety** — all storage write paths (including `record_timer_fired`) strictly use explicit sync options, preventing non-durable write leakage
- ✅ `WorkflowEngineService` — `StartSession`, `CommitStep`, `GetGraph`
- ✅ `IdempotencyService` — `CheckIdempotencyCache`, `RenewLease`, `ReleaseLease`
- ✅ RocksDB-backed append-only event graph
- ✅ Sequence ordering guard — optimistic concurrency for step commits
- ✅ Graph-position arbitration — a lease is refused before execution when the position is already
  committed, or claimed by a different step identity
- ✅ Sequence claim authorization — sequence claims are strictly cleared only by the current lease owner
- ✅ Maximum lease lifetime (`CELLAFLOW_MAX_LEASE_LIFETIME_MS`) — a worker that hangs while still
  heartbeating is eventually reclaimed, with fencing tokens making the reclaim safe
- ✅ Boot recovery — session reconstruction and timer respawning on startup
- ✅ TLS support (cert + key via environment variables)
- ✅ Bearer token and `x-api-key` authentication interceptor
- ✅ gRPC reflection (v1 + v1alpha)
- ✅ OTLP telemetry (traces + metrics)
- ✅ Health check HTTP server (`/health/ready`)

Docker: `ghcr.io/cellaflow/cellaflow:latest`
