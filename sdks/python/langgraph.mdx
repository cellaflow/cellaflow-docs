# LangGraph Integration

`CellaflowSaver` is a drop-in replacement for LangGraph's in-memory checkpointer. It persists your `StateGraph` checkpoints to the CellaFlow engine — giving your LangGraph workflows **crash recovery, time-travel debugging, and cross-agent state isolation** without changing your graph definition.

Beyond checkpointing, `durable_tools` makes a node's irreversible side effects happen [at most once](#leased-tool-calls-inside-nodes) — across a crash, a restart, or a resumed thread.

---

## Installation

```bash
pip install "cellaflow[langgraph]"
```

<Note>
If your environment already has `langgraph >= 0.2.0` and `langgraph-checkpoint >= 2.0.0`, the `[langgraph]` extra is optional — `from cellaflow import CellaflowSaver` will work out of the box.
</Note>

## Basic Usage

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from cellaflow import CellaflowSaver

# 1. Initialize the checkpointer
checkpointer = CellaflowSaver(target="localhost:50051", secure=False)

# 2. Define your state schema
class AgentState(TypedDict):
    query: str
    plan: str
    report: str

# 3. Define nodes
def planner(state: AgentState) -> dict:
    return {"plan": f"Plan for: {state['query']}"}

def reporter(state: AgentState) -> dict:
    return {"report": f"Report based on: {state['plan']}"}

# 4. Build the graph
builder = StateGraph(AgentState)
builder.add_node("planner", planner)
builder.add_node("reporter", reporter)
builder.add_edge(START, "planner")
builder.add_edge("planner", "reporter")
builder.add_edge("reporter", END)

# 5. Compile with CellaFlow persistence
app = builder.compile(checkpointer=checkpointer)

# 6. Run with a thread_id (maps to a CellaFlow session)
config = {"configurable": {"thread_id": "research-session-42"}}
result = app.invoke({"query": "autonomous AI agents"}, config)
print(result)
```

## Crash Recovery

If your process crashes mid-graph, re-invoke with the same `thread_id`. CellaFlow replays committed checkpoints and resumes from the last committed node:

```python
# Original run crashes after "planner" node
result = app.invoke({"query": "autonomous AI agents"}, config)
# → Crashes here

# Resume — "planner" checkpoint is replayed, "reporter" runs live
result = app.invoke({"query": "autonomous AI agents"}, config)
```

No changes to your graph definition required.

## Time-Travel & State Inspection

`CellaflowSaver` implements the full LangGraph checkpoint interface, including `list()` and `get()` for time-travel:

```python
# List all checkpoints for a session
for checkpoint_tuple in checkpointer.list(config):
    print("Checkpoint ID:", checkpoint_tuple.checkpoint["id"])
    print("State:", checkpoint_tuple.checkpoint["channel_values"])
    print("---")

# Get a specific checkpoint by ID
checkpoint = checkpointer.get(config)
print("Current state:", checkpoint["channel_values"])
```

Use this to inspect agent state at any point in the graph's execution history — useful for debugging long-running research or analysis workflows.

## Multi-Turn Conversations

`thread_id` maps directly to a CellaFlow session. Use different `thread_id` values for different conversation threads:

```python
# Thread 1
config_1 = {"configurable": {"thread_id": "user-alice-session-1"}}
app.invoke({"query": "climate change"}, config_1)

# Thread 2 — completely isolated state
config_2 = {"configurable": {"thread_id": "user-bob-session-1"}}
app.invoke({"query": "stock markets"}, config_2)

# Continue Thread 1 — replays from last checkpoint
app.invoke({"query": "climate change follow-up"}, config_1)
```

## Leased Tool Calls Inside Nodes

A checkpointer makes your graph's **state** durable. It does nothing for a node's **side effects**.

If a node charges a customer and the process dies before the next checkpoint lands, the resumed run re-enters that node and charges again. The state is recovered perfectly; the money moved twice.

`durable_tools` closes that window. Wrap the invocation, and any `@tool` called inside a node body is leased — it runs at most once per thread, across crashes and restarts.

```python
from cellaflow import CellaflowSaver, durable_tools, tool

@tool(tool_name="issue_refund")
def issue_refund(ticket_id: str, cents: int) -> dict:
    return payment_gateway.charge(ticket_id, cents)   # irreversible

def refund_node(state):
    return {"receipt": issue_refund(state["ticket"], state["amount"])}

app = builder.compile(checkpointer=CellaflowSaver(target="localhost:50051"))
config = {"configurable": {"thread_id": "ticket-4417"}}

with durable_tools(config):
    app.invoke({"ticket": "T-4417", "amount": 2499}, config)
```

If that process dies after the charge, a new one resuming the thread re-runs the pending node — and the lease answers from the recorded result instead of calling the gateway:

```
phase 1: process exited with 17, ledger has 1 charge(s)
phase 2: resumed and completed, ledger has 1 charge(s)
```

The node ran twice. The customer was charged once.

<Note>
Use the context manager rather than assembling the equivalent by hand. A tool's idempotency key is derived from its session id, and `durable_tools` derives that session from the thread — **stable** across restarts, so the lease still recognises the earlier attempt, and **separate** from the checkpointer's own session, so the two never compete for positions in the graph. A `@tool` called outside `durable_tools` raises rather than running unleased.
</Note>

### Using it with the checkpointer you already have

`durable_tools` does not go through the checkpointer — it establishes the context the `@tool` reads and talks to the engine directly. Leasing therefore works with whichever `BaseCheckpointSaver` you already use, so adopting it does not mean moving your checkpoint storage.

```python
from langgraph.checkpoint.postgres import PostgresSaver
from cellaflow import durable_tools, tool

with PostgresSaver.from_conn_string(DB_URI) as checkpointer:
    checkpointer.setup()
    app = builder.compile(checkpointer=checkpointer)

    with durable_tools(config):
        app.invoke({"ticket": "T-4417", "amount": 2499}, config)
```

Checkpoints go to Postgres exactly as before; the node's irreversible tool call is leased. The same holds for `MemorySaver`, or any other checkpointer.

### Two nodes calling the same tool

Under the default `SCOPE_SESSION_WIDE` the key is derived from the tool name and arguments, **not** the graph position — which is what lets the guarantee survive a resume, since LangGraph re-runs only the pending node and therefore reaches tools in a different order than the first run did.

The consequence: two *different* nodes calling the same `tool_name` with the same arguments in one thread deduplicate into a single execution. Give them distinct `tool_name`s, or an explicit `idempotency_key`, when they are genuinely different operations.

### When replicas disagree about the arguments

The derived key hashes the tool's arguments, so two replicas reaching the same node with **different** arguments derive different keys and do not contend — as far as the engine can tell, they are unrelated operations.

Passing an explicit key makes them converge:

```python
@tool(tool_name="issue_refund", idempotency_key=f"refund-{ticket_id}")
```

That prevents the double charge, with a trade-off worth stating plainly: the replica that loses receives a result computed from arguments it did not supply. If they disagreed about the amount, the loser is handed a refund for someone else's number.

The durable fix is to make the disputed value itself a leased step, so the replicas agree on it before reaching the step that spends it.

## Checkpointer Configuration

```python
checkpointer = CellaflowSaver(
    target="localhost:50051",   # Engine gRPC address
    secure=False,               # Set True for TLS in production
)
```

For production, set `CELLAFLOW_AUTH_TOKEN` in your engine environment, and the SDK reads the token automatically.

## How it maps to CellaFlow primitives

| LangGraph concept | CellaFlow equivalent |
|:---|:---|
| `thread_id` | Session ID |
| Checkpoint | Step commit in the event graph |
| Node execution | `@step` — committed after completion |
| Graph state | MessagePack-serialized payload in the event graph |
| `list()` / `get()` | `GetSessionGraph` RPC |
| `@tool` inside a node | Idempotency lease with a fencing token |
