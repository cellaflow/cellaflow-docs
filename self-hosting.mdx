# Self-Hosting

The Cellaflow engine is distributed as a Docker image. This page covers running it locally for development and deploying it in production with TLS and authentication.

---

## Docker (Local Development)

The fastest way to get started:

```bash
docker run -d \
  --name cellaflow \
  -p 50051:50051 \
  -p 9090:9090 \
  -e CELLAFLOW_ALLOW_UNAUTHENTICATED=true \
  ghcr.io/cellaflow/cellaflow:0.3.0
```

Pin a version, as above, rather than `latest`. A version's image is never rewritten from 0.3.0 on, so you always know which build, and which licence terms, you are running; `latest` moves with every release.

<Warning>
**The engine refuses to start without a token or
`CELLAFLOW_ALLOW_UNAUTHENTICATED=true`.** With neither set, every caller would be
accepted, and nothing in the process can tell a laptop from a reachable host, so
the decision is yours to state rather than the engine's to guess. Omit both and
the container exits at boot with:

```
No authentication token is configured, so every caller would be accepted.
Set CELLAFLOW_AUTH_TOKEN to require credentials, or set
CELLAFLOW_ALLOW_UNAUTHENTICATED=true to serve without them deliberately.
```

Failing at boot rather than at the first request means an orchestrator shows you
a crash-looping container instead of quietly serving an open port. Use the opt-out
for local development only; anywhere else, set a token.
</Warning>

| Port | Purpose |
|:---|:---|
| `50051` | gRPC API (SDK connections) |
| `9090` | Health check HTTP server |

Check health:

```bash
curl http://localhost:9090/health/ready
# {"status":"ready"}
```

## Persistent Storage

By default, RocksDB data is written inside the container and lost on restart. For persistent state, mount a volume:

```bash
docker run -d \
  --name cellaflow \
  -p 50051:50051 \
  -p 9090:9090 \
  -v $(pwd)/cellaflow-data:/data \
  -e CELLAFLOW_ALLOW_UNAUTHENTICATED=true \
  ghcr.io/cellaflow/cellaflow:0.3.0
```

## Docker Compose

For local multi-service setups, use Docker Compose:

```yaml
# docker-compose.yml
services:
  cellaflow:
    image: ghcr.io/cellaflow/cellaflow:0.3.0
    ports:
      - "50051:50051"
      - "9090:9090"
    volumes:
      - ./cellaflow-data:/data
    environment:
      - CELLAFLOW_API_KEY=your-secret-key
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9090/health/ready"]
      interval: 10s
      timeout: 5s
      retries: 5
```

```bash
docker compose up -d
```

## Authentication

Start the engine with a token to require it on every gRPC call:

```bash
docker run -d \
  --name cellaflow \
  -p 50051:50051 \
  -e CELLAFLOW_API_KEY=your-secret-key \
  ghcr.io/cellaflow/cellaflow:0.3.0
```

Give your agents the same value in `CELLAFLOW_API_KEY`, and every call the SDK makes sends it, with no code change:

```bash
export CELLAFLOW_API_KEY=your-secret-key
```

Or pass it explicitly:

<CodeGroup>
```python Python
@workflow(version="1.0.0", target="engine.internal:50051", secure=True, api_key=key)
def my_workflow(input: str) -> str: ...
```

```ts TypeScript
await durableTools(threadId, { target: "engine.internal:50051", secure: true, apiKey: key }, async () => {
  // ...
});
```
</CodeGroup>

<Note>
Sending a key needs SDK **0.10.0 or later** (`cellaflow` on PyPI, `@cellaflow/sdk` on npm). Earlier
versions send no key, so an engine that requires one refuses every call with `UNAUTHENTICATED`.
</Note>

- **One variable on both sides.** The SDKs read only `CELLAFLOW_API_KEY`. The engine reads `CELLAFLOW_AUTH_TOKEN` first and falls back to `CELLAFLOW_API_KEY`, so set only `CELLAFLOW_API_KEY` on the engine too. Leave `CELLAFLOW_AUTH_TOKEN` unset rather than blank: a blank one counts as set and leaves the engine with no token. Compose writes a blank value for `${VAR}` when the variable is unset.
- **A blank value means no key**, and the SDKs read no other variable.
- **No key in plaintext to another machine.** With `secure=False` (the default) and a target that is not this machine, the SDK refuses the call rather than send the key in the clear. On a network you trust, such as a Compose network or a Kubernetes service, set `CELLAFLOW_ALLOW_PLAINTEXT_KEY=true`, and the SDK warns once per target instead. Anywhere else, use [TLS](#tls).
- **On the wire** the key travels as `authorization: Bearer <key>`. The engine also accepts `x-api-key: <key>`.

## TLS

Provide a certificate and private key for TLS:

```bash
docker run -d \
  --name cellaflow \
  -p 50051:50051 \
  -e CELLAFLOW_TLS_CERT=/certs/cert.pem \
  -e CELLAFLOW_TLS_KEY=/certs/key.pem \
  -e CELLAFLOW_API_KEY=your-secret-key \
  -v $(pwd)/certs:/certs \
  ghcr.io/cellaflow/cellaflow:0.3.0
```

Connect from the SDK with `secure=True` (`secure: true` in TypeScript):

```python
@workflow(version="1.0.0", target="engine.internal:50051", secure=True)
def my_workflow(input: str) -> str: ...
```

The SDKs trust the usual public certificate authorities. For a certificate issued by your own CA, or a self-signed one, point them at it: `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH=/path/to/ca.pem` for Python, which gRPC then trusts instead of its bundled roots, and `NODE_EXTRA_CA_CERTS=/path/to/ca.pem` for Node, which adds it to Node's.

## Environment Variables

Two of these have a **different default in the container image than in the binary**, because the
image sets them itself. The distinction matters when running the binary directly.

| Variable | Description | Binary default | Image default |
|:---|:---|:---|:---|
| `CELLAFLOW_HOST` | gRPC bind address | `[::1]` — loopback only | `::` |
| `CELLAFLOW_PORT` | gRPC port | `50051` | `50051` |
| `CELLAFLOW_DB_PATH` | RocksDB data directory | `./cellaflow_data` | `/data/cellaflow` |

| Variable | Description | Default |
|:---|:---|:---|
| `CELLAFLOW_API_KEY` | The token every call must present, as `authorization: Bearer` or `x-api-key`. The engine also reads `CELLAFLOW_AUTH_TOKEN`, before this one; set only one, and leave the other unset rather than blank | None |
| `CELLAFLOW_ALLOW_UNAUTHENTICATED` | Serve with no credentials, deliberately. Required to boot when no token is set | `false` |
| `CELLAFLOW_TLS_CERT` | Path to TLS certificate file (PEM) | None (cleartext) |
| `CELLAFLOW_TLS_KEY` | Path to TLS private key file (PEM) | None (cleartext) |
| `CELLAFLOW_MANAGEMENT_PORT` | HTTP health server port | `9090` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP/gRPC endpoint for traces and metrics. `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` and `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` set one signal each, and `CELLAFLOW_OTLP_ENDPOINT` is read last | None: nothing is exported |
| `CELLAFLOW_LOG_LEVEL` | Log level | `info` |
| `CELLAFLOW_BACKEND` | Storage backend | `rocksdb` |
| `CELLAFLOW_SESSION_IDLE_TIMEOUT_SECS` | Idle seconds before a session evicts from memory | `1800` |
| `CELLAFLOW_ACTOR_SEND_TIMEOUT_MS` | Wait for room on a session's mailbox before shedding with `RESOURCE_EXHAUSTED` | `5000` |
| `CELLAFLOW_MAX_LEASE_LIFETIME_MS` | Ceiling on a single lease, independent of heartbeats | `3600000` (1 hour) |
| `CELLAFLOW_SYNC_WRITES` | fsync each durable write before acknowledging it | `true` |

Most variables also accept an unprefixed fallback (`HOST`, `PORT`, `DB_PATH`, `AUTH_TOKEN`,
`API_KEY`).

<Warning>
**Running the binary directly? `CELLAFLOW_HOST` defaults to `[::1]` — loopback only.** The engine
will start, report healthy, and refuse connections from anywhere else, with no error to explain
it. Set `CELLAFLOW_HOST=::` (or `0.0.0.0`) to accept external traffic. The Docker examples on this
page do not pass it because the image already sets it; if you extract a command from one of them
to run a locally built binary, you have to add it.
</Warning>

<Warning>
**`CELLAFLOW_SYNC_WRITES` is the durability/latency dial.** Left at `true`, an acknowledged commit
has reached stable storage and survives host power loss, not just a process or container failure.
Set it to `false` and a commit is acknowledged once the write reaches the operating system's page
cache — faster, and safe if your failure model is pods dying rather than hosts losing power. The
cost of syncing is roughly 0.1–0.4 ms per commit on a local NVMe SSD and largely disappears under
concurrent load, where RocksDB group-commits writers into a shared sync; on network-attached storage
it is considerably higher. Measure on your own storage rather than assuming either way.

**`CELLAFLOW_MAX_LEASE_LIFETIME_MS` is safe to raise and unsafe to lower.** It exists because a
worker that hangs *without dying* heartbeats forever and would otherwise hold its lease — and its
graph position — indefinitely. But reclaiming a worker that is merely slow lets a second worker
repeat a side effect the first may already have performed. Set it above your slowest legitimate
tool call, not near it.
</Warning>

## Health Checks

The engine exposes an HTTP health server on the management port (`CELLAFLOW_MANAGEMENT_PORT`,
default `9090`):

| Endpoint | Status | Meaning |
|:---|:---|:---|
| `GET /health/ready` | `503` | Engine is booting (boot recovery in progress) |
| `GET /health/ready` | `200 {"status":"ready"}` | Engine is fully initialized and accepting gRPC connections |

<Warning>
Do not route gRPC traffic to the engine until `/health/ready` returns 200. The engine performs boot recovery (session reconstruction + timer respawning) before accepting connections — attempting to connect during recovery will fail.
</Warning>

## Observability

Cellaflow emits OpenTelemetry traces and metrics to an OTLP collector. In local development, you can use the OpenTelemetry Collector or Jaeger:

```bash
# Run Jaeger locally
docker run -d \
  --name jaeger \
  -p 4317:4317 \
  -p 16686:16686 \
  jaegertracing/all-in-one:latest

# Then run the engine pointing to it
docker run -d \
  --name cellaflow \
  -p 50051:50051 \
  -e CELLAFLOW_OTLP_ENDPOINT=http://jaeger:4317 \
  -e CELLAFLOW_ALLOW_UNAUTHENTICATED=true \
  ghcr.io/cellaflow/cellaflow:0.3.0
```

Open Jaeger UI at `http://localhost:16686` to inspect traces.
